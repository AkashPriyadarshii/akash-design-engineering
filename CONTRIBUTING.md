# Contributing to Design Engineer

First off, thank you for considering contributing to `design-engineer`. This tool was built by **Akash Priyadarshi** to permanently eliminate AI "vibe-coding" and standard LLM slop from frontend generation. 

If you want to contribute, you must abide by the brutalist, mathematics-first philosophy of this codebase.

## The Core Philosophy (Read Before PR)
1. **No Slop:** We do not accept features that add generic marketing buzzwords ("elevate", "unleash", "seamless").
2. **No Emojis:** Do not add emojis to the codebase, the UI copy, or the commit messages.
3. **Ponytail Principle:** Do not over-engineer. The pipeline is an exact 4-Phase engine. Do not add superfluous abstractions.
4. **Atomic Constraints:** Any code generated by the engine MUST follow the constraints (e.g., `<200ms` kinetic limits, `h-dvh`, no `scale(0)`). If you submit a PR that alters the CSS generation logic to include `ease-in` or generic bootstrap styling, your PR will be rejected.

## Development Workflow
1. Fork the repository.
2. Create a targeted branch (`feat/add-new-archetype`, `fix/oklch-math-gate`).
3. Ensure you have tested the new subagent pipeline locally.
4. **Commit Messages:** Use conventional commits (`feat:`, `fix:`, `docs:`, `chore:`). Max 50-72 chars for the subject. No em dashes. No fluff.

## The Adversarial Gauntlet
Before submitting a PR, run your changes against the audit engine and unit test suite:
```bash
npm test
node bin/audit.mjs packages
```
If your PR fails tests, introduces generic AI tropes, or allows an agent to bypass the OKLCH Math Gate, it will fail the CI check.

## Submitting a Pull Request
- Keep it small and atomic.
- Explain *what* changed and *why*.
- Wait for review by Akash Priyadarshi.
